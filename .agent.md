# envault Development Agent

## Project Purpose

envault is a cross-platform CLI tool and background daemon (Go) that automatically discovers, versions, and backs up `.env` files. It uses SHA-256 content-addressed storage (like git) and supports macOS (launchd) and Linux (systemd).

## Tech Stack

- **Language**: Go
- **CLI Framework**: Cobra (`github.com/spf13/cobra`)
- **Platforms**: macOS (darwin/amd64, darwin/arm64), Linux (linux/amd64, linux/arm64)
- **CI/CD**: GitHub Actions (`.github/workflows/release.yml`)

## Project Structure

- `main.go` — entry point
- `cmd/root.go` — all CLI commands
- `internal/config/` — config management (~/.envault/config.json)
- `internal/store/` — content-addressed blob store + version index
- `internal/scanner/` — recursive .env file discovery
- `internal/daemon/` — background daemon + OS service install
- `scripts/build-release.sh` — cross-compile build script

## Commit & Release Workflow

**After every set of meaningful changes, follow this workflow:**

1. **Build and verify**:
   ```
   go build -o envault .
   ```

2. **Commit with a conventional commit message**:
   - `feat:` for new features
   - `fix:` for bug fixes
   - `docs:` for documentation
   - `refactor:` for code restructuring
   - `release:` for release-related changes

3. **Push to the develop branch**:
   ```
   git add -A && git commit -m "<type>: <description>" && git push origin develop
   ```

4. **For releases** (when the user asks to publish/release, or after significant features):
   - Bump the version tag (check latest with `git tag --list 'v*' --sort=-v:refname | head -1`)
   - Tag and push:
     ```
     git tag v<NEXT_VERSION>
     git push origin v<NEXT_VERSION>
     ```
   - The GitHub Actions workflow automatically builds all 4 platform binaries and publishes a GitHub Release.

5. **Update the installed binary locally** after building:
   ```
   sudo cp envault /usr/local/bin/envault
   ```

## Code Conventions

- Keep the single-file CLI pattern (`cmd/root.go`) — all commands in one file
- All internal packages under `internal/` — not importable by external code
- Use `0600` permissions for sensitive files, `0700` for directories
- Skip directories: `node_modules`, `.git`, `vendor`, `build`, `dist`, `.envault`
- Match env files: `.env`, `.env.*`, `*.env`
